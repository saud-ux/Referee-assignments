نظام تكليف حكّام تنس الطاولة

مكتب تكليفات يرشّح الحكّام للبطولات ويرسل لهم التكليف على واتساب بزرّي «أنا متوفّر» و«أعتذر»، ويعرض ردودهم لحظياً في لوحة التحكم.

Saudi Table Tennis Federation — Referee Assignment Office
مبني على Node.js + Express · تخزين قابل للتبديل JSON / Firestore · مراسلة عبر WhatsApp Cloud API

١

نبذة عن النظام

نظام «مكتب التكليفات» يدير البطولات والحكّام، ويرسل لكل حكم تكليفاً على مستوى البطولة (فترتها ومكانها) عبر رسالة واتساب تحمل زرّي رد سريع: أنا متوفّر وأعتذر، ويظهر رد الحكم مباشرة في لوحة التحكم.

التكليف على مستوى البطولة لا المباراة: يؤكّد الحكم توفّره للحضور خلال فترة البطولة، ويُحدَّد تكليفه اليومي على الأرض في التجمّع. يتكامل النظام مع نظام السكوربورد القائم لسحب البطولات والمباريات دون إدخال يدوي.

٢

خصائص تشغيلية

  • يعمل بالكامل عبر الإنترنت — كل ما يحتاجه الحكم متصفّح لفتح رابط الرد، دون تثبيت أي تطبيق.
  • يبدأ فوراً في الوضع التجريبي: كل شيء يشتغل، لكن الرسائل تُطبع في الطرفية بدل إرسالها، مع إمكانية تسجيل رد الحكم يدوياً لاختبار المسار كاملاً قبل ربط واتساب.
  • يعمل على أي جهاز فيه متصفح (لابتوب، جوال، تابلت) للوحة التحكم ولصفحة رد الحكم على السواء.
  • قابل للنشر على استضافة دائمة (مثل Render) لاستقبال الويبهوك، وبتكلفة تشغيل منخفضة.
٣

التقنيات المستخدمة (Tech Stack)

الواجهة الأمامية

HTML5 / CSS3 / JavaScript خام دون إطار عمل · مكتبة SheetJS (XLSX) v0.18.5 لاستيراد الجداول من Excel · خطوط IBM Plex Sans Arabic وZain.

الخادم

Node.js ≥ 20 · إطار Express v4.19 · وحدات ES Modules أصلية.

التخزين والمزامنة

ملف محلي JSON افتراضياً، أو Firebase Firestore عبر firebase-admin v12 — بنفس الواجهة دون تغيير الكود.

المراسلة

WhatsApp Cloud API عبر Meta Graph API v21.0 — رسائل قوالب بأزرار رد سريع، وتحقّق توقيع HMAC-SHA256.

التكامل

سحب البطولات والمباريات من Firebase Realtime Database الخاصة بنظام السكوربورد.

الاستضافة

الخادم يقدّم اللوحة وAPI والويبهوك من عملية واحدة · مناسب لمنصّات مثل Render.

المعمارية: خادم Express واحد + طبقة تخزين قابلة للتبديل (ملف محلي ⇆ Firestore) + تكامل خارجي مع واتساب والسكوربورد. المتصفّح لا يكتب في التخزين مباشرة، بل يمرّ عبر API الخادم.

آلية العمل والربط

١) دورة التكليف: إنشاء بطولة وإضافة الحكّام ← إنشاء تكليف لحكم (يمنع النظام تكرار تكليف قائم) ← الإرسال عبر واتساب ← رد الحكم ← تحديث الحالة فوراً في اللوحة + رسالة تأكيد للحكم.

٢) فصل الكتابة عن الواجهة: المتصفّح يستدعي API الخادم فقط، والخادم وحده يكتب في التخزين عبر طبقة store موحّدة (ملف محلي أو Firestore).

٣) الربط مع واتساب: يُرسَل قالب معتمد بزرّي رد سريع، ويعود الرد إلى /webhook بحمولة ACCEPT:<id> أو DECLINE:<id>؛ ويُرسَل تأكيد نصّي مجاني للحكم داخل نافذة الـ٢٤ ساعة.

٤) المسار البديل (رابط الرد): إذا لم يُفعّل واتساب، لكل تكليف رابط سرّي /r/:token يفتح صفحة فيها زرّا التوفّر والاعتذار، فيُسجَّل الرد بنفس الأثر.

٥) مهلة الرد: مهمّة دورية كل ١٠ دقائق تحوّل التكاليف التي تجاوزت مهلة الرد (٦ ساعات افتراضياً) إلى الحالة expired.

٦) التكامل مع السكوربورد: يقرأ النظام matches.json من Firebase Realtime Database الخاصة بالسكوربورد لاستيراد البطولات والمباريات دفعة واحدة.

٧

الإرسال عبر واتساب والتكلفة

يعتمد النظام على قالب واتساب من فئة المنفعة باسم referee_availability_ar باللغة العربية، مع زرّي رد سريع (الأول للتوفّر والثاني للاعتذار). ولكل بطولة رابط قروب واتساب اختياري يظهر للحكم بعد قبوله التكليف.

ربط واتساب عند اعتماد النظام

يبدأ النظام في الوضع التجريبي دون واتساب، ويُفعَّل الربط الفعلي مع واتساب عند تعميد/اعتماد استخدام النظام رسمياً — عندها تُرسَل التكاليف تلقائياً بدل الرابط، وتصل ردود الحكّام مباشرة عبر أزرار واتساب.

وضمن هذا الربط، سيُنشِئ النظام قروب واتساب باسم البطولة تلقائياً، ويُضاف إليه كل حكم عند موافقته على التكليف — فيجتمع حكّام كل بطولة في قروبها الخاص دون إنشاء يدوي أو نسخ روابط.

المزايا الوظيفية

  • تكليف فردي وجماعي: ترشيح حكم واحد أو إرسال دفعة لعدة حكّام في بطولة واحدة، مع منع تكرار التكاليف القائمة.
  • إدارة كاملة للتكليف: إعادة الإرسال، الإلغاء، وتسجيل الرد يدوياً إن ردّ الحكم هاتفياً.
  • استيراد مرن: إضافة الحكّام والبطولات والمباريات من نص، أو من ملف Excel، أو مباشرة من السكوربورد.
  • متابعة لحظية للحالات: pending قيد الإرسال · sent بانتظار الرد · accepted متوفّر · declined اعتذر · expired انتهت المهلة · cancelled ملغى · failed فشل الإرسال.
  • صفحة رد بسيطة للحكم برابط خاص، وزر انضمام لقروب البطولة عند القبول.
٩

النموذج الأمني

  • كل رابط رد يحمل رمزاً سرّياً غير قابل للتخمين (24-byte base64url)، وهو وحده ما يحمي صفحة الرد العامة.
  • التحقق من توقيع ميتا على كل ويبهوك عبر HMAC-SHA256، إضافة إلى verify token لتأكيد الاشتراك.
  • المفاتيح والإعدادات الحسّاسة تُقرأ من متغيّرات البيئة (Environment Variables)؛ ومفتاح خدمة Firebase يُخزَّن في FIREBASE_SERVICE_ACCOUNT فقط.
  • الخادم لا يفتح مجلّد المشروع كاملاً، بل يقدّم ملفات الواجهة بالاسم حتى لا تنكشف ملفات الخادم.
  • حماية اللوحة اختيارياً عبر ADMIN_PASSWORD وSESSION_SECRET عند النشر.
